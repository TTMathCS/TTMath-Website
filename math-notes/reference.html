Part A — Properties of congruences

Recall a ≡ b (mod n) means "n divides a − b" — a and b sit at the same spot on an n-hour clock. Every legal move is in the table below (a ≡ b and c ≡ d (mod n) throughout; k is any integer).

Handiest consequence of the multiply/power rules: when computing, replace any number by anything congruent to it at any step — that's why 49 ≡ −1 (mod 25) makes 49¹⁹ easy.

The one trap: you cannot always divide. From c·a ≡ c·b (mod n) you may not simply cancel c — the correct rule is a ≡ b (mod n / gcd(c, n)), and only when gcd(c, n) = 1 does c cancel cleanly.
Example: 2·3 ≡ 2·0 (mod 6) (both sides ≡ 0), yet 3 ≢ 0 (mod 6) — dividing by 2 fails because gcd(2,6)=2. To "divide," multiply by the modular inverse instead (which exists only when gcd = 1).

Part B — Popular theorems, in brief

Core — the four this class is built on

Chinese Remainder Theorem  this class

Statement. If n₁, …, nₖ are pairwise coprime (gcd(nᵢ, nⱼ) = 1, i ≠ j), the system x ≡ aᵢ (mod nᵢ) has exactly one solution modulo N = k∏i=1 nᵢ.

What it's for. It turns one hard modulus into several easy ones: solve the problem separately mod each prime piece, then glue the answers into a single number. The glue step is the whole reason "split → solve → recombine" works.

Example. x ≡ 2 (mod 3), 3 (mod 5), 2 (mod 7) has the unique answer x = 23 (mod 105). → explained · proof

Fermat's Little Theorem  this class

Statement. If p is prime and p ∤ a, then a^(p−1) ≡ 1 (mod p).

What it's for. The exponent-crusher. Since the powers of a return to 1 every (p−1) steps, only the exponent mod (p−1) matters — so a monstrous power collapses to a tiny one.

Example. 3⁶ ≡ 1 (mod 7), so for 3¹⁰⁰ reduce 100 mod 6 = 4: 3¹⁰⁰ ≡ 3⁴ = 81 ≡ 4 (mod 7). It also underlies the fast primality test for choosing RSA primes. → explained

Euler's Theorem  generalizes Fermat

Statement. If gcd(a, n) = 1, then a^φ(n) ≡ 1 (mod n), where φ(n) (Euler's totient) counts how many of 1, …, n share no factor with n.

What it's for. Fermat for any modulus, not just primes — when n is composite, p−1 no longer works but φ(n) does. When n = p is prime, φ(p) = p−1 and you recover Fermat exactly.

Example. φ(10) = 4 (the coprime ones are 1, 3, 7, 9), so 3⁴ = 81 ≡ 1 (mod 10). This is the engine behind why RSA decryption returns the original message.

Order of an element & primitive roots  this class

Statement. The order ordn(a) of a mod n is the smallest d with aᵈ ≡ 1 (mod n), and it always divides φ(n): ordn(a) | φ(n). If some a has order exactly φ(n), it is a primitive root.

What it's for. The order is the length of the repeating cycle of powers. A primitive root generates every coprime residue by its powers — the basis of discrete logarithms and Diffie–Hellman key exchange.

Example. Order of 2 mod 7 is 3 (cycle 2, 4, 1). But 3 is a primitive root mod 7: its powers 3, 2, 6, 4, 5, 1 hit all six nonzero residues. → Problem 4

Good to know — popular beyond this class

Wilson's Theorem

Statement. (p−1)! ≡ −1 (mod p) if and only if p is prime.

Why it's true (sketch). Mod a prime, pair every number with its inverse; only 1 and p−1 are their own inverse, so the whole product collapses to 1·(p−1) ≡ −1.

Example. (5−1)! = 24 ≡ 4 ≡ −1 (mod 5). A neat primality test in theory, though far too slow for large p.

Euler's criterion & quadratic reciprocity

Statement. For odd prime p and p ∤ a, a is a perfect square mod p exactly when a^((p−1)/2) ≡ 1 (mod p) (and ≡ −1 if it is not). The Legendre symbol (a | p) = ±1 records the answer.

What it's for. Deciding whether x² ≡ a has a solution, without searching. Quadratic reciprocity then links (p | q) to (q | p), so you can flip a hard symbol into an easier one.

Example. Is 2 a square mod 7? 2³ = 8 ≡ 1 → yes (indeed 3² = 9 ≡ 2). Central to cryptography and computing square roots mod p.

Lagrange's theorem (polynomials mod p)

Statement. A nonzero polynomial of degree d has at most d roots modulo a prime p.

What it's for. It caps how many solutions a congruence can have — the same way a degree-d equation has at most d real roots. (It can fail for composite moduli, which is why we split to primes first.)

Example. x² ≡ 1 (mod 7) has exactly two roots, x = 1 and x = 6 — not more. This is what bounds the solution count in a problem like 2(c).

Lifting the Exponent (LTE)

Statement. Under the right conditions (e.g. p divides a − b but not a or b), it gives the exact power of p dividing aⁿ − bⁿ: v_p(aⁿ − bⁿ) = v_p(a − b) + v_p(n).

What it's for. Counting how many times a prime divides a difference of powers, instantly — a favourite olympiad shortcut for divisibility problems.

Example. How many times does 3 divide 10⁹ − 1? Since 3 | (10 − 1), LTE gives v₃ = v₃(9) + v₃(9) = 2 + 2 = 4.

Carmichael function λ(n)

Statement. λ(n) is the smallest exponent that works for every coprime base at once: a^λ(n) ≡ 1 (mod n) for all gcd(a, n) = 1. It always divides φ(n).

What it's for. A sharper Euler — sometimes the true universal exponent is much smaller than φ(n), which matters for efficiency and for the exact RSA correctness proof.

Example. λ(8) = 2 (every odd a satisfies a² ≡ 1 (mod 8)), even though φ(8) = 4.

Hensel's lemma  advanced

Statement. If a polynomial has a simple root mod p (one where the derivative isn't 0), that root lifts to a unique root mod p², p³, …

What it's for. The bridge from "solve mod a prime" to "solve mod a prime power" — you solve the easy case mod p, then climb. It's the missing rung when CRT alone isn't enough.

Example. Start from the root x = 3 of x² ≡ 2 (mod 7). Hensel produces a root mod 49, then mod 343, by nudging the value while keeping it ≡ 3 (mod 7):

mod 7:    x = 3       (3²  = 9     ≡ 2)
mod 49:   x = 10      (10² = 100   ≡ 2)
mod 343:  x = 108     (108²= 11664 ≡ 2)
How do you know it's 10, then 108?

At each step there are only 7 numbers it could be — so you check them. The new root must stay ≡ 3 (mod 7) (shrink-the-modulus rule), so below 49 the only candidates are 3 plus multiples of 7:

candidates (3 + 7t):   3, 10, 17, 24, 31, 38, 45
square mod 49:          3²=9,  10²=100≡2 ✓,  17²≡44,  …
→ only 10 works, so the root mod 49 is 10

Same idea one level up: the root must now stay ≡ 10 (mod 49), so the candidates are 10 plus multiples of 49:

candidates (10 + 49s): 10, 59, 108, 157, 206, 255, 304
square mod 343:         10²≡100,  59²≡51,  108²=11664≡2 ✓
→ only 108 works, so the root mod 343 is 108

Shortcut — solve instead of guessing. With x = 3 + 7t:

(3 + 7t)² ≡ 9 + 42t (mod 49)  →  9 + 42t ≡ 2  →  6t ≡ −1 (mod 7)  →  t = 1  →  x = 10

That one-line equation gives t directly (and the next level gives s = 2). Either way you are building x one base-7 digit at a time: 3, then 3 + 1·7 = 10, then 10 + 2·49 = 108 — each new power of 7 fixes the next digit, earlier digits never change.

Lucas' theorem  advanced

Statement. A binomial coefficient mod a prime p equals the product of binomials of the base-p digits: write m and k in base p, then C(m, k) ≡ ∏ C(mᵢ, kᵢ) (mod p).

What it's for. Computing C(m, k) mod p for huge m without the giant factorial — and quickly telling whether p divides it.

Example. Is C(10, 3) divisible by 3? In base 3, 10 = 101 and 3 = 010; the digit 0-choose-1 = 0 appears, so the product is 0 — yes, 3 divides it.

How they connect. CRT splits a composite modulus into primes; Fermat / Euler / order handle each prime piece; Hensel climbs from a prime p up to its powers pᵏ. Together they reduce almost any "mod n" question to small prime calculations.
